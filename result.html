🔍 Key Observations from Item Analysis

  • Q9 (Confidence) scored highest (mean 4.30) — users generally felt confident while navigating the system.
  • Q5 (Integration) scored well (mean 4.05) — features feel cohesive and well-connected.
  • Q4 (Technical Support Needed) scored 3.05 — many respondents felt they might still need guidance, indicating room for better onboarding.
  • Q8 (Cumbersome) scored 3.00 — some users found the system burdensome, consistent with the SOS discoverability complaints.
  • Q10 (Learning Curve) scored 3.20 — a notable number of respondents needed time to understand the system before use.

Key Issues Identified

⚠️ Usability Issues Found During Testing

During the heuristic evaluation and usability testing sessions, the following key issues were identified and documented across different usability dimensions. Issues are tagged by severity based on how frequently they were raised.

  • 🆘
    SOS Button Discoverability High Severity Multiple respondents explicitly reported difficulty finding the SOS/emergency button. Comments included: "I can't find the SOS immediately," "the SOS should be found easily," and "I have a hard time finding it." This is a critical safety feature that must be prominently placed. Also one of our heuristic evaluation finding identified this issue.
  • ⚠️
    No Cancel Confirmation Dialog High Severity One respondent noted: "when I cancel some actions, it immediately goes — I didn't see a warning." The lack of a confirmation prompt when cancelling rides or actions can lead to accidental loss of bookings. Same as one of our heuristic evaluation in in no error message for cancel booking and add a place.
  • 🔘
    Button Functionality Clarity Low Severity One respondent mentioned buttons need to be "sure it actually directs" and should be "easy to understand," suggesting that some interactive elements were unclear in their purpose or response.

Qualitative Feedback

💬 What Did Respondents Like?

The following are selected responses from respondents about what they appreciated about the Sakay Partido system:

  • "Very convenient app and easy to use."
  • "I like that the system helps commuters easily find available transportation, especially for passengers who live far from terminals."
  • "It saves time since I no longer need to ask around or wait long just to get transport details."

  • "Overall I like it especially since I'm a commuter."

  • "The system itself is pretty good — it would be convenient for people who do not have anyone to fetch them. Considering that we don't have a system like that here, that would be very effective to use."
  • "I like this because there is no app like Angkas in the Partido area."
  • "It is easy to use and convenient for passengers."

🛠️ What Improvements Were Suggested?

The following are selected improvement suggestions gathered from respondents:

  • "Make things (like buttons) easy to understand and ensure they are functional. When booking a ride, the SOS should be activated automatically so it won't be missed."
  • "The SOS should be easy to find — I had a hard time locating it."
  • "When cancelling actions, a warning or confirmation message should appear first."
  • "If I need emergency help immediately, I can't find the SOS button quickly enough."

Discussion

💬 Interpretation of Results

The Sakay Partido prototype received an overall mean SUS score of 63.25 which falls within the "Acceptable" usability range according to standard SUS grading scale (51–67.9). The system shows basic usability according to the assessment results but needs additional improvements before reaching the "Good" threshold which requires a score of 68 or higher. The system must undergo essential enhancements before it can be used by a wider audience.

The design structure and feature set of the system show intuitive and coherent functionality because users achieved high scores in Q9 which recorded a mean of 4.30 for "I felt very confident using the system" and Q5 which received a mean score of 4.05 for "The functions were well integrated. Regular commuters who use smartphones established immediate connections with the core concept which created trust in them. The positive qualitative responses consistently praised the app's convenience and its potential to solve a real gap in local transportation — the absence of ride-booking apps in the Partido area.

The majority of respondents perceived easier system navigation according to lower Q4 Technical Support and Q10 Learning Curve scores which received 1.95 and 1.80 respectively. The standard deviation of 15.37 indicates that users experienced different levels of satisfaction since some users considered the system to be Excellent with an 85.0 rating while others gave it a Poor rating of 37.5. The differing user experiences resulted from users' previous knowledge of ride-hailing applications together with their ability to find hidden features such as the SOS button.

For summary, the SOS button discoverability problem represents the main usability issue which affects system safety for users.

Recommendations

✅ Recommendations for Improving the Prototype

Based on the SUS scores, heuristic evaluation findings of us(Sakay Patido Development Team), and qualitative feedback from respondents, the following improvements are recommended for the next version of the Sakay Partido prototype.

🆘

Relocate the SOS Button

Place the SOS/emergency button in a fixed, always-visible location (e.g., top right of the home page) so users can access it instantly.

📍

Make the Location Access Mandatory

Make the Location Access mandatory for the users to use the app for real-time tracking of drivers and their location.

🚫

Add Cancel Confirmation Dialog

Implement a confirmation modal whenever the user attempts to cancel a ride or perform a destructive action. This prevents accidental cancellations and improves user control.

🔘

Improve Button Labeling & Clarity

Ensure all buttons use clear, action-oriented labels. Avoid ambiguous icons without text. Provide hover/tap states to confirm user interaction.

Suggested Design Improvements

🎨 Design-Level Enhancements

Beyond functional fixes, the following design-level changes are suggested to elevate the user interface quality and align the prototype more closely with established mobile UX standards.

1

SOS Emergency Access

Adding SOS button in Homepage can solve the issue of having a hard time finding it. A prominently colored (red) SOS emergency button should remain accessible at all times during an active ride session. This directly addresses the most frequently told usability concern.

2

Consistent Component Library

Standardize button sizes, padding, and typography across all screens. Define a shared component set (primary button, secondary button, input fields, cards) so every screen feels cohesive. This addresses the inconsistency noted in the heuristic evaluation.

3

Mandatory Location Access

Making the Location Access mandatory for the users to use the app for real-time tracking of drivers and their location.

4

Error Handling Messages

Putting a clear and concise error handling messages to Cancel Booking and Saving a Place based on each members heuristic evaluation and the respondents usability evaluation.
